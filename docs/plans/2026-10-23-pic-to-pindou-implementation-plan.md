# 图片转拼豆图纸 · 实施计划

在浏览器内把一张图片转成 Artkal S 色号的拼豆图纸：可预览成品、可手改单格、可导出带色号与用量表的 PNG。PC 与移动端都能用。

## 范围

**做**：上传图片 → 调参 → 预览 → 手改 → 导出 PNG 图纸。
**不做**：跨品牌色号映射（ADR-0001）、账号与云端作品库（ADR-0002）、PDF 分板打印、完整像素编辑器（画笔/油漆桶/选区/图层）、自动抠图。

## 技术栈

Vite + React 19 + TypeScript + Tailwind CSS + zustand + Vitest + Biome。无路由，无 UI 组件库。

## 数据模型

```ts
type BeadCode = string                                    // "S01"
type PaletteEntry = { code: BeadCode; name: string; hex: string; lab: Lab }

/** 0 = 空白格；i + 1 = palette[i] */
type BeadGrid = { cols: number; rows: number; cells: Uint16Array }

type ConvertParams = {
  cols: number; rows: number        // 豆格数，由板数预设或直接输入推导
  beadSizeMm: 2.6 | 5 | 10          // 只影响成品物理尺寸与颗数换算，不参与转换
  maxColours: number                // K，8–40
  dither: boolean
  blankColours: string[]            // 被当作空白格的源图颜色（sRGB hex）
  brightness: number; contrast: number; saturation: number
}

type ConvertResult = {
  grid: BeadGrid
  usedCodes: BeadCode[]             // 实际用到的色号，下标与 grid 的 i 对齐
  counts: number[]                  // 各色号的颗数
}
```

`beadSizeMm` 刻意不进入转换 —— 同一张图纸在三种豆规格下网格数据完全通用，换规格只是换物理尺寸的换算常数。

## 阶段

### P0 脚手架

1. `npm create vite` 初始化 React + TS 模板，清掉示例代码。
2. 装 Tailwind、zustand、Vitest、Biome，配好 lint 与 test 脚本。
3. 建目录骨架：`domain/` `workers/` `render/` `state/` `ui/` `export/`。
4. 落地色卡 `domain/palette/artkal-s.ts`：159 条 `code / name / hex`，LAB 在模块初始化时算一次。

**验收**：`npm run dev` 起得来；`npm run test` 能跑通一条占位测试；色卡条数断言为 159，色号无重复。

> 色卡 HEX 目前来自第三方整理，**色号编号可信、HEX 有偏差风险**。P0 内拿官方色卡核对一遍，有出入以官方为准并记在提交说明里。

### P1 domain 基础（纯函数 + 单测）

1. `colour.ts`：sRGB ↔ LAB 转换、CIEDE2000 色差。
2. `sample.ts`：源图 + 网格尺寸 → 网格分辨率的像素采样。面积平均为主；源图尺寸接近目标网格整数倍时切最近邻。
3. `grid.ts`：`BeadGrid` 构造、空白格语义、颗数统计、物理尺寸换算（格数 × 豆规格）。
4. `pattern.ts`：图纸排版的元数据——图例条目、行列坐标标签、每格是否标注色号的判定。

**验收**：CIEDE2000 用公开测试对（Sharma 等人的 34 组）验过；采样在纯色图上结果精确匹配；`grid` 统计与手工算例一致。

### P2 量化与 Worker

1. `quantise.ts`：k-medoids 在色卡内选 K 色（按像素计数加权）→ 逐格映射到选中集合 → 可选误差扩散抖动。
2. `workers/convert.worker.ts`：消息协议 `{ requestId, pixels, w, h, params }` → `{ requestId, grid, usedCodes, counts }`。
3. 主线程侧封装：`requestId` 单调递增，过期结果直接丢弃（不做队列，只认最后一次）。

**验收**：200×200 转换在 Worker 内完成，主线程无长任务；连续拉滑块 20 次只应用最后一次结果；K=8/16/40 下实际用色数均 ≤ K 且全部存在于色卡。

### P3 渲染层

1. `beadTile.ts`：单颗豆的离屏模板（豆身 + 中心孔 + 轻微阴影）。
2. `drawPreview.ts`：视口裁剪 + 按格宽切换画法（≥6px 铺豆模板，<6px 走 `ImageData`，见 ADR-0003）。
3. 共用坐标变换：缩放、平移、设备像素比。

**验收**：200×200 适应窗口时稳定 60fps；跨过 6px 阈值画面不跳；同一网格在豆子模式与扁平模式下色块位置逐格对齐。

### P4 布局与参数面板

1. 断点布局：PC 三栏（左参数 · 中画布 · 右用量），移动端画布满屏 + 底部抽屉三档（参数 / 用量 / 图片）。
2. 参数控件：板数预设（1/2/4/9 块 29×29）与自由颗数输入、豆规格切换、色数滑块、抖动开关、亮度/对比度/饱和度。
3. `UsagePanel`：按颗数降序列出用到的色号、名称、颗数、成品物理尺寸。
4. 空状态与转换中的进度提示。

**验收**：1440px 与 390px 两个宽度下都能完整操作；参数任一变更后预览在 300ms 内更新；改豆规格时成品尺寸数字跟着变而画面不变。

### P5 手势与轻编辑

1. 查看态：单指/鼠标拖动平移、滚轮与双指缩放（以指针为锚点）、双击适应窗口。
2. 编辑态：显式按钮进入，单指涂色、双指平移缩放；一次按下到抬起记为一步撤销。
3. 橡皮 = 涂成空白格；色板选色后即为画笔颜色。
4. 撤销栈：网格快照，深度 50；重算前若存在手改，弹确认提示「将丢弃 N 处手改」。

**验收**：默认参数下两者压测 3 分钟，不掉帧、不误触缩放；连续涂 30 格后一次撤销全部回退；重算确认框的计数与手改格数一致。

### P6 图纸导出

1. `drawPattern.ts`：离屏 Canvas 合成图纸 —— 网格线、行列坐标、图例（色块 + 色号 + 名称 + 颗数）、成品尺寸与总颗数说明。
2. 格数 ≤ 40 时每格标注色号，超过则只标行列坐标 + 图例（自适应）。
3. 空白格画成浅灰空心圆（代表板上露出的钉），与白色豆在视觉上可区分。
4. 导出 PNG，每格 24px，宽度上限 8192px。

**验收**：29×29 图纸放大能看到每格色号；200×200 图纸不标格内色号但仍可照图施工；空白格与 S01 白豆在同一张图里能分辨。

### P7 收尾

1. 界面上标注「屏幕色仅供参考，实物存在色差」。
2. 超过上限时提示「超过 X 颗，建议分图」。
3. 移动端真机过一遍上传、缩放、涂色、导出。
4. 性能复测：首次转换耗时、稳定态内存占用。

**验收**：手机上完整走通一次真实使用；内存无持续增长。

## 风险

| 风险 | 处置 |
|---|---|
| 色卡 HEX 与实物偏差 | P0 核对官方色卡，界面标注仅供参考 |
| 200×200 在手机上操作困难 | 编辑态保证可放大到单格足够大；必要时后续加放大镜辅助 |
| 抖动产生的孤立色点被当成错误 | 默认关闭，开关旁写明代价 |
