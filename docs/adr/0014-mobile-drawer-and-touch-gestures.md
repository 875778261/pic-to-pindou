# 窄屏：画布满屏，三档抽屉挤在底下

宽屏维持「参数 · 画布 · 用量」三栏（`lg:` 起，1024px）。窄屏换一副外壳：画布占满剩余高度，底部一条常驻 tab 条，参数 / 用量 / 图片三档点开点收。

## 两个外壳，不是两套组件

`WideShell` 与 `MobileShell` 只差布局，内容组件（`ParameterPane`、`PreviewStage`、`UsagePanel`、`DropZone`）是同一批。两套 DOM 同时存在会让每个文件输入各有一个，谁被点到全凭运气，所以用 `useMediaQuery('(min-width: 1024px)')` 二选一渲染。

## 抽屉挤压画布，不盖住它

抽屉是 flex 流里的一段，展开时画布被压缩，不是浮在画布上。理由是一条票面要求：**切换模式的按钮在画布上始终可达**。盖住式抽屉会把右上角那排按钮（适应 / 编辑中 / 豆形）压在底下，画笔徽标也会重叠。压缩画布代价是画布变矮，但看得全、点得到，且收起抽屉就回来了。

抽屉三档之间切换不关抽屉、不清任何状态：三档回答的是「看什么」，不是「去哪」。

## 触摸上两套手势，一套单指一套双指

- 查看态单指平移、双指缩放平移；编辑态单指涂色、双指缩放平移。单指做什么由模式决定，双指做什么两个模式都一样——双指想看细节，两种情况下都该看得到细节。
- 双指第二根按下时正在涂的那一笔当场收尾：**没划过格就撤掉那一格、不进撤销栈**。双指缩放前，第一根手指总要先落在画布上，那一下不是落笔，是本想双指。
- 双指没全抬起来时，剩下那根指头不接管成单指动作，免得收指的瞬间又画一格。

## 贴边只做到网页能做的那一步

画布 `touch-action: none`，页面 `overscroll-behavior: none`，抽屉内容区自己滚（`overscroll-contain`）。浏览器级的贴边回退与 iOS 左缘返回手势是系统行为，网页拦不住，写进已知边界。

**Status**: accepted

**Considered Options**：
- 可拖动 sheet（半屏 / 全屏 / 吸附）（否决——多一套拖动手势，还要判它与画布手势谁优先，收益只有「拖着玩」）
- 抽屉盖住画布（否决——模式按钮与画笔徽标被遮，票面明写「不被抽屉遮挡」）
- 编辑态第一下延迟落笔、等有没有第二根指头（否决——涂色失去即时反馈，手感塌了）
- 双指按下时不撤那一格（否决——每次双指缩放都白涂一格，用户得手动撤销）
- 两套 DOM 并存、靠 CSS 切（否决——两份文件输入、两份滚动手柄，重复组件的状态会分叉）
- 抽屉做成第四个 tab「画笔」（否决——票面定死三档；画笔归参数档）

**Consequences**：
- 断点只有一处定义：`useMediaQuery` 的 1024px 与 Tailwind 的 `lg:`。两边改一处就得改另一处。
- 画笔条只在抽屉的参数档里出现，画布上留一个徽标当入口；宽屏则直接贴在画布下。
- `PreviewStage` 的 `fill` 形态：不写底部操作提示、不画内嵌画笔条，省下的高度给画布。
- 撤销栈不受布局影响：抽屉开合、切档、切外壳都不进历史。
