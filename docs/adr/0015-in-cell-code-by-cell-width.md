# 格内色号按格宽判定，且只属于导出图纸

图纸是照着摆的那张纸，格内不写色号就只剩行列坐标配图例，摆到半张纸就迷路。原判定「单边 ≤ 40 格才标」是按「塞得下 4 个字符」定的，但 MARD 色号实际只有 2–3 个字符（291 色的 283 个色号里，3 字符 173 个、2 字符 110 个），这个阈值把最常用的 29×58 预设挡在了外面 —— 而那正是用户最需要格内色号的尺寸。

所以判定依据从「格数」换成「格宽」，并接受字号的降级：

1. **格宽优先，字号守住底线。** 排版从首选 24px 往下试：24px（字号约 9px）→ 21px（字号 8px，最后一档真正舒服的）→ 画布上限允许的最小格宽，硬下限 14px（字号 6px，3 字符极限挤压）。14px 仍超上限才退回行列坐标配图例。宁可格子缩到 14px，也不把 6px 字硬塞进 12px 的格子里糊成一团。
2. **判定收口到 `cellFitsCode(cellSize)`。** 阈值只写在函数里一处，排版、绘制、面板文案三处都问它。「格宽够不够标」以后只有一份答案。
3. **`labelled` 从输入变成排版的输出。** 格宽是排版算出来的，判定只能在排版之后发生；面板文案与绘制都读排版结果，不再各自拿格数重算一遍。
4. **只属于导出图纸，预览不标。** 预览的职责是远观判断效果；满屏色号与这个用途冲突，而且预览格宽随缩放变化，同一张图会时标时不标。预览认色走两条现成的路：点一颗豆报出这一格的色号，用量面板列出全部色号与颗数。
5. **分图不在本轮。** 按 29×29 板切页是让 200×200 在纸上真正可读的唯一办法，但它会牵动「图例以整张图纸为 SSOT」这条（ADR-0008），单独立项。

**Status**: accepted（第 1 条的「从 24px 逐像素往下试」与第 2 条「判定驱动搜索」被 ADR-0017 取代：格宽改为恒定 24px，`cellFitsCode()` 退化为事实判断，14px 这条阈值本身保留）

**Considered Options**：
- 保留「单边 ≤ 40 格」阈值（否决 —— 29×58 这个最常用预设一上来就不标，恰好把最需要色号的尺寸排除在外）
- 只放大纸张、不缩格宽（否决 —— 200 格时单边 8192 与面积 1670 万像素两个上限会先顶到）
- 按实测色号宽度动态判（否决 —— 要量文字就把画布掺进纯判定，而 2–3 字符的宽度差不足以换来这份复杂度）
- 预览也标色号（否决 —— 与预览的用途冲突，且格宽随缩放变化会让标注忽隐忽现）
- 本轮就把分图做掉（否决 —— 改动面比色号本身大数倍，会把一件能当天收的事拖成一件要重排图例的事）

**Consequences**：
- `labelsCellCodes(cols, rows)` 退役，`LABELLED_CELL_LIMIT`（格数阈值）随之删除；导出按钮的提示文案改由排版结果驱动。
- 41–200 格区间从「只有坐标」变成「有格内色号」，代价是这些尺寸的格宽被压到 21px 以下。
- 200×200 实测落在 18–21px 格宽、6px 字号：能标，纸上偏小，属于「不崩不糊」的承诺范围，不在「纸上可读」的承诺里。
- ADR-0008 第 1 条（格数 ≤ 40）被本 ADR 取代，其余条款（扁平色块、图例格式、坐标 1/5/10 分档、两条画布上限）继续有效。
