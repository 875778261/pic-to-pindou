# 色号是唯一标识，系列只出字母

界面上任何地方需要「这个颜色叫什么」，答案只有色号。MARD 没有官方色名，也没有公布系列语义：上游数据集每条只给 `code / hex / rgb / group`，`group` 就是色号前缀的字母本身；用户提供的页面快照里同样没有中文系列名。仓库里曾有一张「A 黄橙、B 红粉、C 蓝青、D 绿色、E 紫色、F 棕咖、G 黑白灰、H 荧光、M 过渡」的表，来源是印象而非数据。

这张表与色卡本身对不上。按 291 色逐色算 HSL 色相、按系列取均值：

| 系列 | 条目 | 平均色相 | 曾标注 | 实际情况 |
|---|---:|---:|---|---|
| A | 26 | 41° | 黄橙 | 相符 |
| B | 32 | 111° | 红粉 | 绿 |
| C | 29 | 198° | 蓝青 | 相符 |
| D | 26 | 264° | 绿色 | 蓝紫 |
| E | 24 | 330° | 紫色 | 粉紫 |
| F | 25 | 0° | 棕咖 | 红 |
| G | 21 | 低彩度 | 黑白灰 | 肤色与灰混排 |

至少三处错得能一眼看出来（图上写着「红粉」、色块是绿）。用户是拿这张图纸去下单的，错的中文名比没有中文名更贵。

因此：

- **不编造系列语义。** 界面上出现系列时只出字母（`A`、`ZG`），与已有的 P / R / Q / T / Y 一致。
- **`SERIES_LABELS` / `seriesLabel()` / `seriesDisplayName()` 整组删除**，不留「返回裸字母」的假抽象。将来若拿到权威来源，加回来是一个函数的事。
- **`seriesOf()` 与 `materialOf()` 保留**：字母前缀与标准/特种的划分都有数据依据（前者来自 `group`，后者见 ADR-0006）。

**Status**: accepted

**Considered Options**：
- 按实测色相重写中文名（否决——有依据仍是猜；G 系列肤色与灰混排、M 是过渡色，靠色相定不下边界，等于用一次新的猜测替换一次旧的猜测）
- 保留现状等权威来源（否决——图纸正面现在就写着错名字，等的每一天都在误导下单）
- 保留函数但返回裸字母（否决——调用方要字母直接拼即可，多一层只会让人以为它承载语义）
- 用材质（标准色 / 特种色）充当「名称」（否决——一张图里绝大多数都是标准色，列出来几乎全是同一个词，没有区分度）

**Consequences**：
- 图例条目只剩「色块 + 色号 + 颗数」，不再有名称列（见 ADR-0008）。
- 术语表、`docs/reference/README.md` 的系列表、spec 的故事 36 都要同步改写：不能再出现「看到编号和名称」这类要求。
- 色号成为唯一的跨界面标识：屏幕摘要、用量面板、导出图纸三处显示的是同一个字符串，不做任何美化或翻译。
