# 轻编辑：一笔一步，重算要问一声

预览画布右上角有一个「编辑」开关。进编辑态后拖动即涂色、按住空格拖动才挪画布；橡皮把格子涂成空白格。查看态一切照旧（点豆标成不摆豆、双击回适应）。

## 一笔一步

撤销的单位是**一次按下到抬起**，不是一格。拖着连涂三十格，撤一次全回去：逐格记撤销的话，涂错一笔要点三十次才退得掉，那不叫撤销。

栈里存整张图纸，不是补丁。一次拖动可能涂几十格，记补丁要为每格维护正反两向；而整张 200 × 200 图纸不过 80KB 一份，深度 50 封顶 4MB，比补丁的簿记便宜得多。

## 栈里除了图纸还有参数

撤销一格还要把参数一起带回去，否则画面与滑块对不上：改了尺寸重算、再撤销，图纸回到旧的 29 × 29，参数面板却仍写着 200。所以栈里的一格是三件套——图纸、它当时的参数、以及它对应的那张转换产物。第三件让「这张被手改过几格」数得准：手改数 = 图纸与转换产物之间不同的格数。

## 重算要问，但只在有手改时问

调参、换尺寸都会重算，重算会把图纸整个换掉。有手改时先弹一句「重算会丢弃 N 处手改」，两个出口：放弃改动（参数回滚到上一次真正生效的值，图纸不动）、继续重算。

**没有手改的重算不弹窗、也不进撤销栈。** 滑块一次拖动能触发十几次重算，每次都进栈会把 50 步全填成参数中间态，手改版本被挤出去——而用户按撤销想找的正是那个手改版本。所以普通重算只是把「当前」顶替成新图纸，历史照旧留着；只有被手改拦下过的那一次，才真记一步，撤销能回手改版。

## 编辑态不绑双击

双击回适应在查看态是顺手的，在编辑态会顺手涂掉一格——双击的第一次点击就是一笔涂色。所以编辑态不绑双击，改用画布上的「适应」按钮。这是「切换模式不误涂」的延伸：误涂不只来自切模式那一刻。

## 色板列全色卡

291 个色号按系列字母分组、横向滚动。只列本图已用的色号最省事，但手改常是为了加一个原图上没有的颜色——比如给眼睛补一颗黑豆，那就恰恰不在已用列表里。

## 拖动要补格

指针走快了会从一个格直接跳到隔了几格的位置，只处理当前格会留下一串漏涂。所以一次移动要沿两点连线把中间的格补齐（`cellPath()`），再整笔重画。

## 已知边界

- 撤销栈不跨图：换一张源图就清空。两张图的手改之间没有可撤销的关系。
- 重算失败（超上限被拒）时栈清空——那张图纸已经不存在了，留着它的手改版本也回不去。
- 触摸手势（双指平移缩放、抽屉）归 #9，本票只做桌面。

**Status**: accepted

**Considered Options**：
- 逐格记撤销（否决——涂错一笔要点几十次，撤销失去意义）
- 栈里只存图纸不存参数（否决——撤销后画面与滑块对不上）
- 每次重算都记一步（否决——滑块会填满整条栈，手改版本被挤掉）
- 重算不入栈、手改丢了找不回（否决——与「重算后撤销仍能回退到有手改那张」直接冲突）
- 编辑态也绑双击回适应（否决——双击的第一次点击就是一笔涂色）
- 色板只列已用色号（否决——想加一个新颜色就没有入口）
- 编辑态右键拖动平移（否决——触控板用户不好按，且与右键菜单打架）
- 手改就地改 `pattern.grid.cells`（否决——撤销要的是互不相干的旧版本，就地改会把栈里的历史一起改掉）

**Consequences**：
- 撤销与重做会同时改 `pattern`、`params`、`conversionBase` 三者，谁也不能单独动。
- 「有没有手改」用引用比较：当前图纸的网格与转换产物不是同一个对象即有手改。
- 用量面板、摘要卡、导出图纸都读 `pattern`，手改后自然同步，不需要额外通知（ADR-0012）。
- 重算拦截发生在唯一的转换入口 `convertCurrent()`，任何改参数入口都自动受约束。
