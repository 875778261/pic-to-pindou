# 装图只做裁切，比例靠尺寸联动保住

拼豆板是方的（29×29），用户的图大多不是。把原图装进网格只有三种基本做法：拉伸铺满、居中裁切、留白（contain）。
拉伸会毁掉人脸与宠物的比例，而那是本产品的主要题材；留白会在方形网格里留下成片空白格，玩家不会为空白去买板。
裁切只删掉画面边缘，观感与板的面积都不浪费。

因此只保留两条路：

- **比例锁定**（默认开）：改宽或改高，另一边按原图宽高比自动算。网格比例≈原图，既不裁切也不变形。
- **裁切**：用户关掉锁定、自己定尺寸时，居中剪掉超出网格比例的部分。

不提供拉伸，也不提供留白。板数预设走裁切路径——点「4 块」等于「我要用满 2×2 块板」，得到 58×58，比例锁定自动关掉，面板写明原图将被裁成什么形状。预设给的网格不一定是方形：2 块是 29×58。

**Status**: accepted

**Considered Options**：
- 拉伸铺满（否决——变形肉眼可见，人物与宠物会一眼看出不对）
- 留白 contain（否决——方形网格装 3:2 的图，上下各留五分之一空白格，那是白送的板面积）
- 三种都给、藏进高级选项（否决——拉伸与留白都没有真实需要的场景，多一个选项就是多一条要解释的分支）

**Consequences**：
- `ConvertParams` 多一个装图方式字段，采样层要算裁切原点；`convert()` 仍是唯一测试接缝，测试只断言「裁切后第一格与最后一格对应源图哪一像素」这类外部可观察结果。
- 比例锁定时网格比例会被取整，差最多一格。这种情况走铺满而不是裁切——那一格级的差异用铺满消化掉，比平白丢一条边划算。
- 将来真要做拉伸，是给装图方式加一个取值，不动现有语义。
