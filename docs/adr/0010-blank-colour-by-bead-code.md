# 空白色按色号标记，量化跑两遍

用户点预览里的一颗豆，那个**色号**在图纸里全部变成空白格：不摆豆、不计颗数、不进图例。可以连续标多个，逐个可撤。

## 为什么按色号，不按源图颜色

源图颜色在采样后逐格都带噪声，逐格精确比对只能命中「与点击处数值完全相同」的那些格。拿一张 290 × 290 的白底测试图实测（白底每像素加 ±3 单值噪声、超出 255 截断，主体是一块红与一条深蓝；290/29 = 10 走最近邻采样）：

| 量 | 值 |
|---|---:|
| 白底格数 | 621 |
| 白底里出现的不同颜色值 | 4 种 |
| 与左上角格数值完全相同、会被逐格比对抹掉的格 | 365 |
| 仍然留着、照样长成白豆的格 | 256（41%） |

这还是噪声极窄的合成图。真实照片受 JPEG 与光照影响，同一片白底会散得更开。票面要的是「白底照片不会再长出一圈白豆」，逐格精确比对做不到。

按色号就稳：量化本来就把每一格归到色卡里的一个色号，同一个色号就是屏幕上同一种豆。点它，等于说「这种豆不摆」。

**相邻但不同的颜色不会被一起抹掉**，因为不同色号是不同条目，各自独立判定；这里不引入任何 ΔE 容差或相似色合并——那才会连带把相邻的近似色一起吃进去。

## 为什么跑两遍

第一遍正常量化，得到「每格是哪个色号」，落在被标色号上的格就是用户点的那些豆。第二遍把空白色号排出候选集、把这些格排除出选色权重，腾出的名额回到剩下的画面。

只做「量化后改写成空白格」不重选，会留下两个后果：白底照样占掉 16 个名额里的一个；而且第一遍的选色是被面积最大的背景主导的。实测同一张图标掉两个色号后，剩 2 个色号、132 颗，颜色没有被背景挤掉。

第一遍只在确实标了空白色时才需要：没有空白色、或标的色号在图纸里不存在（换图、换档位后常见），都只有一遍，性能与从前一致。

## 点哪里

点预览画布上的一颗豆，不新开源图视图。预览就是源图的量化结果，点到的正是屏幕上那颗豆；将来预览换成豆形渲染（ADR-0003 的 6px 切换），画布与格坐标不变，这套点击判定照旧。

与 spec 手势一节的「显式按钮切换查看态 / 编辑态」不冲突：这里点的是**选色**，不是往画布上涂色，误触的代价是「某个色号被标成不摆豆」，面板上看得见、一点可撤。等到加缩放平移手势时（#9）这条要重新审：那时单击会与拖拽起手竞争，得先分清是点击还是拖动。

## 已知边界

重选色号会改动「每格是哪个色号」，所以个别原本挨着空白色的格可能改成邻色，而不是跟着变空白。连点验证（白底合成图三次、照片两次）里点到的格每次都变空白，未观察到该现象；要不付这个代价就得让空白色号继续占名额，见下方选项。

## 其余判定

- **色卡里没有的色号直接忽略。** 换档位或换图后旧标记不解释成别的颜色，也不报错。
- **换图不清空空白色。** 参数跨图保留是既有约定（色号上限、明暗都保留），空白色号同理；面板上写着「已标 N 种」，状态可见、一点可撤。
- **抖动时空白格不参与误差扩散**：它们不产豆，既不该往外扩散误差，也不该接住邻居的误差，否则空白区会把偏色推回画面。

**Status**: accepted

**Considered Options**：
- 比对量化前的源图颜色（原实现）：照片白底抹不干净，见上表的 41%
- 相似色合并（ΔE 容差内一起抹）：违背「相邻但不同的颜色不会被一起抹掉」
- 量化后把格改写成空白、不重选：空白色号白占名额，选色被背景主导
- 新增源图预览再点：要多写一套装图几何（fit / crop）把点击落回格子，而最终仍得落到色号粒度，等于多一层会出错的东西
- 把标记写进网格（与手改同源）：重算会覆盖手改，用户标的空白色号会跟着丢

**Consequences**：
- `params.blankColours`（sRGB hex）改名 `blankCodes`（色号）；实现计划里「被当作空白格的源图颜色」那句作废。
- 有空白标记时量化跑两遍；没有时仍是一遍。
- 图例与颗数不必改口径：空白格编码 0 本来就不计入任何色号、也不进图例。
- 空白色号是**参数**，橡皮（#8）是**手改**：重算会覆盖手改，但不会覆盖空白色号。两者在网格里同写 0，语义不同源。
- 换一张图后，记着的空白色号未必在图上存在：标了不存在的色号时图纸与原样一致，不提示。
