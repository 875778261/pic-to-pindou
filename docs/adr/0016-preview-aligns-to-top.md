# 预览内容贴着画布上沿摆，不纵向居中

`placement()` 原来一条规则管两个方向：内容比视口小的那个方向始终居中，比视口大的不留空白。横向的图（如 29×12）放进高容器时，格宽被高度方向的富余撑到顶，纵向只剩三百多像素，于是图案从画布中线偏下的位置开始 —— 顶部一大片空白，看起来像是「图掉下去了」。

决策是把纵向与横向拆开，各用各的对齐：

1. **纵向贴顶。** 装得下时原点为 0，图案贴画布上沿；装不下时守 pan，pan 为 0 也贴起始边。纵向原来那个居中分支整个删掉 —— 一种情况一条规则，临界点天然连续。
2. **横向保持居中。** 预览被左右分栏夹在中间，横向居中读起来是自然的；改成贴左反而让图案挤在左边、右侧空一片。用户抱怨的是纵向，横向不动。
3. **工具条的避让交给 CSS，不进几何。** 对齐到 0 之后，浮在右上角的「适应 / 编辑 / 豆形」会压住图案，所以承载区在顶部让出一条。这条留白如果写进 `placement()`，居中值在「装得下 → 装不下」的临界点恰好是 0，加上固定边距会让图案在放大跨过临界点时凭空跳一个边距的高度。

**Status**: accepted

**Considered Options**：
- 贴顶但在 `placement()` 里留固定上边距（否决 —— 临界点会跳，理由见第 3 条）
- 不动对齐，改为让预览卡高度由内容决定（否决 —— 左栏参数一长，卡片照样被拉高，治不了根）
- 两个方向一起改成贴左上（否决 —— 横向居中在分栏布局里是自然的，改贴左只是把空白挪到右边）

**Consequences**：
- `axis()` 从「一条规则管两轴」变成两轴各一套对齐，`viewport.test.ts` 里那条「网格比视口小时居中、比视口大时贴住左上」要按轴拆成两条断言。
- `Viewport` 里 `panX / panY` 的注释「相对居中摆放的偏移」对纵向不再成立，改为「相对贴边摆放」。
- ADR-0011 中「原点是内容小于视口就居中」的纵向那一半被本 ADR 取代，横向那一半与「两套画法共用一份摆放」整体继续有效。
